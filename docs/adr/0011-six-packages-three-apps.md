# Six packages, three apps: separation along seams

The monorepo is maximally separated along architectural seams — three Bun apps (compose services) and six packages, each owning one boundary: `apps/api` (REST/SSE server, serves the built Angular statics), `apps/worker` (run orchestrator, spawns ephemeral run containers per ADR-0003), `apps/web` (Angular v22 dashboard, spec-first per ADR-0006); `packages/domain` (Zod schemas + DTO contracts), `packages/persistence` (Drizzle schema, entities, queries on Postgres per ADR-0002), `packages/job-queue` (queue + scheduler on Postgres, no Redis), `packages/agent-core` (AI SDK v5 loop, tool assembly, MCP clients), `packages/platform-mcp` (Link → MCP client factory; GitHub adapter first per ADR-0010), `packages/qa-runtime` (Playwright QA driver + video capture). Chosen for maximum modularity and maintainability; the accepted cost is seam ceremony, which is the point: every package maps to a real boundary (stack, isolation, platform integration), not file-level fragmentation.
